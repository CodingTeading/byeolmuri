# 학습 플러그인

이론과 실습을 한 화면에 둔다. 왼쪽에는 실제 하늘이 계속 떠 있고, 오른쪽
패널에서 설명이 진행되며, **설명이 넘어갈 때마다 하늘이 그에 맞춰 움직인다.**
천문대에서 선생님이 돔을 돌려가며 설명하는 것과 같은 구성이다.

동영상 강의와 다른 점은 하늘이 **살아 있다**는 것이다. 학생은 설명 도중에도
직접 끌어서 돌려보고, 확대하고, 다른 별을 눌러볼 수 있다.

## 레슨 추가하기

**코드를 건드릴 필요가 없다.**

1. `content/<lang>/<id>.json` 에 레슨을 쓴다
2. 목록을 다시 굽는다

```bash
node tools/make-lesson-index.mjs          # 모든 언어
node tools/make-lesson-index.mjs ko       # 한 언어만
node tools/make-lesson-index.mjs --touch big-dipper ko   # 갱신일을 오늘로
```

`content/<lang>/index.json` 은 **손으로 고치지 않는다.** 본문에서 굽는다.
포털은 본문을 열지 않고 목록만 보고 계절과 갈래를 판단하는데, 손으로 적으면
둘이 어긋나서 겨울 레슨이 여름 첫 화면에 올라온다. 굽는 김에 갈래·수준·단계
같은 필수 항목도 검사한다.

레슨 본문은 목록에서 누를 때 따로 받아온다. 레슨이 늘어나도 첫 화면이
무거워지지 않는다.

## 레슨 형식

`content/ko/big-dipper.json` 이 본보기다. 전체 구조는 이렇다.

```jsonc
{
  "id": "big-dipper",
  "title": "북두칠성은 어디일까?",
  "subtitle": "한 줄 설명",
  "minutes": 8,
  "level": "intro",             // intro · basic · deep
  "track": "target",            // principle · target · measure
  "tags": ["별자리", "북쪽 하늘"],
  "months": [3, 4, 5, 6, 7, 8, 9],   // 초저녁 하늘에 잘 놓이는 달. 없으면 연중
  "intro": "목록에서 보여줄 소개글",
  "steps": [ /* 아래 참고 */ ],
  "credits": "출처를 밝힐 것이 있으면"
}
```

`level` 과 `track` 은 **화면에 그대로 나오는 글이 아니라 열쇳말**이다. 표시할
이름은 `locales/<lang>.json` 의 `learn.level.*`, `learn.track.*` 에 있다.
한국어를 그대로 적으면 다른 언어 화면에서 한국어가 새어 나온다.

### 갈래(track)

레슨을 나누는 축은 난이도도 테마도 아니라 **어떤 질문에 답하는가**이다.

| 갈래 | 성격 | 예 |
|---|---|---|
| `principle` 원리 | 시간을 돌려야 답이 나오는 것 | 계절이 바뀌는 이유 · 달의 위상 · 역행 |
| `target` 대상 | 오늘 밤 실제로 찾아볼 수 있는 것 | 여름 대삼각형 · 오리온성운 |
| `measure` 측정 | 우리가 어떻게 알아냈나 | 별의 밝기 · 별의 색과 온도 |

### 단계(step)

```jsonc
{
  "title": "단계 제목",
  "text": "<p>본문. HTML 을 쓴다. <b>강조</b>는 흰색으로 나온다.</p>",

  "sky": {                     // 하늘 상태. 적은 것만 바뀐다
    "date": "2026-09-15T21:00:00+09:00",
    "lat": 37.5, "lng": 127.0, "elev": 0,
    "home": true,              // 관측지를 사용자가 사는 곳으로 되돌린다
    "az": 0, "alt": 45,        // 방위/고도 (도). lookAt 이 있으면 무시된다
    "fov": 70,                 // 시야각 (도)
    "timeSpeed": 400           // 1=실시간, 0=정지, 400=400배
  },

  "show": {                    // 표시 요소. 적은 것만 바뀐다
    "constellationLines": true,
    "constellationArt": false,
    "constellationLabels": true,
    "constellationBounds": false,
    "onlyPointedConstellation": true,   // 보고 있는 별자리만 표시
    "atmosphere": false,
    "landscape": true,
    "azimuthalGrid": false,
    "equatorialGrid": false,
    "meridian": false,
    "ecliptic": false,
    "dso": true,
    "milkyway": true,
    "dss": false,
    "stars": true
  },

  "lookAt": "* alf UMa",       // 그쪽으로 시야를 옮기고 따라간다
  "select": "* alf UMa",       // 선택해서 오른쪽에 정보를 띄운다
  "clearSelection": true,      // 선택을 푼다

  // 하늘에 직접 표시한다 (아래 "하늘에 표시하기" 참고)
  "highlight": ["* alf UMa", { "target": "* 80 UMa", "radius": 0.07 }],
  "connect":   ["* bet UMa", "* alf UMa", "* alf UMi"],

  "quiz": {
    "q": "질문",
    "opts": ["보기1", "보기2", "보기3", "보기4"],
    "right": 1,                // 0부터 센다
    "explain": "정답 해설. 틀린 이유까지 짚어주면 좋다"
  }
}
```

### 적은 것만 바뀐다

`sky` 와 `show` 는 **그 단계에서 달라지는 것만** 적는다. 나머지는 이전 단계
상태가 이어진다. 그래야 레슨을 읽는 사람도 무엇이 바뀌는지 한눈에 보인다.

이어진다는 말은 **위치와 시각도 이어진다**는 뜻이다. 한 단계에서 `lat`/`lng`
를 주면 뒤 단계도 계속 그 위치다. 되돌리려면 다시 적어야 한다.

레슨은 **앱이 준비를 마친 뒤에**(`initComplete`) 적용된다. 앱이 뜨면서 관측지를
정하고 시각을 "해가 진 직후"로 옮기는데, 그 전에 레슨을 적용하면 레슨이 지정한
날짜가 통째로 덮어쓰인다. 실제로 첫 단계만 엉뚱한 시각으로 뜨는 일이 있었다.

레슨에 들어올 때 디렉터가 그 순간의 하늘(위치·시각·시간 배속·시야·표시 항목)을
적어 두고, 나갈 때 `director.reset()` 이 그대로 되돌린다. 대기를 꺼두거나 시간을
400배로 돌려놓은 채, 또는 관측지를 적도로 옮겨 둔 채 나가면 사용자는 앱이 고장난
줄 안다. 시각은 레슨을 읽은 만큼 앞으로 당겨 두므로 나가면 다시 '지금 하늘'이다.

### 시야를 어디에 둘 것인가

`az`/`alt` 를 짐작으로 적으면 주인공이 화면 구석에 놓인다. 실제로 어디에
뜨는지 재서 적는다. 개발 서버를 띄우고 콘솔에서:

```js
const stel = document.querySelector('#app').__vue__.$stel
const obs = stel.core.observer
obs.utc = new Date('2027-01-20T12:00:00Z').getTime() / 86400000 + 40587
const o = stel.getObj('* eps Ori')
const s = stel.c2s(stel.convertFrame(obs, 'ICRF', 'OBSERVED', o.getInfo('RADEC', obs)))
;[((s[0] * 180 / Math.PI) % 360 + 360) % 360, stel.anpm(s[1]) * 180 / Math.PI]  // [153, 48]
```

천체가 잡히려면 그 방향이 한 번은 그려져 있어야 한다. 화면이 보이지 않으면
타일이 오지 않아 `getObj` 가 계속 실패한다.

**고도 80도가 넘는 곳은 피한다.** 천정 부근을 정면으로 잡으면 화면이 이상해진다.
주인공이 천정 근처라면 시각을 한두 시간 옮겨 고도를 낮추는 편이 낫다.

### 천체 이름

엔진이 아는 이름이어야 한다. 검색창에 쳐서 나오면 쓸 수 있다.

| 종류 | 예 |
|---|---|
| 고유명 | `Dubhe` `Polaris` `Vega` |
| 바이어 부호 | `* alf UMa` `* zet UMa` |
| 메시에 | `M 31` `M 45` |
| NGC/IC | `NGC 224` |
| 별자리 | `CON western UMa` |
| 행성 | `NAME Jupiter` `NAME Moon` |

고유명이 없는 별도 있다. 미자르는 `Mizar` 가 아니라 `* zet UMa` 로 찾아야 한다.
확실하지 않으면 `apps/web-frontend/public/search-index.json` 에서 확인한다.

**이름이 겹치는 천체를 조심할 것.** 같은 바이어 부호를 여러 천체가 주장하는 일이
있다. 엔진은 그중 아무거나 내주는데, 화면에는 조용히 엉뚱한 별에 표시가 그려진다.
실제로 `* eta UMa` 가 알카이드(1.84등급)가 아니라 3.16등급짜리 다른 별로 잡혀
북두칠성 국자 모양이 무너져 있었다. 쌍성도 마찬가지다(`* 61 Cyg` 는 A·B 둘 다
그 이름을 쓴다). 이럴 때는 **고유명**(`Alkaid`)이나 **번호**(`* 85 UMa`,
`HIP 104214`)로 짚는다.

`make-lesson-index.mjs` 가 이것을 검사한다. 색인에 없는 이름과 둘 이상이 주장하는
이름을 찾아 목록 굽기를 멈춘다.

## 콘텐츠를 쓸 때

- **위치는 되도록 지정하지 않는다.** 사용자가 있는 곳의 하늘이어야 오늘 밤
  밖에 나가서 그대로 확인할 수 있다. 위도를 비교하는 레슨처럼 꼭 필요할 때만
  `lat`/`lng` 를 쓰고, 볼일이 끝나면 **`"home": true` 로 돌려놓는다.** 마지막
  단계를 남의 동네 하늘 위에서 맺을 수는 없다
- **마지막 단계는 밖에서 직접 해볼 것으로 맺는다.** 화면 안에서 끝나면
  플라네타리움이지 관측 교육이 아니다
- 퀴즈 해설에는 정답만이 아니라 **왜 다른 보기가 틀렸는지**를 넣는다
- 별 이름의 유래, 문화별 이름 같은 이야기는 기억에 오래 남는다. **모든 레슨에
  하나씩** 넣되 그것이 레슨의 뼈대가 되어서는 안 된다
- 한국 콘텐츠(28수 · 천상열차분야지도 · 견우직녀 · 좀생이별 · 노인성)는 따로
  빼지 않고 **각 레슨 안에 녹인다.** 따로 빼면 부록처럼 보인다
- 날짜를 박을 때는 본문에 연도를 되도록 쓰지 않는다. 별의 자리는 해마다 같지만
  글에 적은 연도는 낡는다. 달과 행성처럼 연도가 꼭 필요한 주제만 밝혀 적는다

## 하늘에 표시하기

"이 별을 보세요" 라고 쓰는 것과 실제로 짚어주는 것은 다르다. 처음 보는
사람은 글만으로는 못 찾는다.

### `highlight` — 동그라미로 짚기

```jsonc
"highlight": [
  "* alf UMa",                              // 이름만 주면 자동 크기
  { "target": "* 80 UMa", "radius": 0.07 }, // 반지름을 도 단위로 지정
  { "ra": 279.23, "de": 38.78 }             // 좌표를 직접
]
```

반지름을 안 주면 **시야각의 1/14** 로 잡는다. 사용자가 확대·축소하면 원 크기도
따라간다. 고정 크기로 두면 넓게 볼 때는 보이지 않고 확대하면 화면을 덮는다.

**가까이 붙은 두 별에는 반지름을 직접 주어야 한다.** 미자르와 알코르는 11.8분
(0.197°) 떨어져 있는데 자동 크기(시야 6°에서 0.43°)로는 두 원이 겹쳐 한
덩어리가 된다. 붙어 있다는 것 자체가 그 단계의 요점인데 그러면 안 된다.

### `connect` — 선으로 잇기

```jsonc
"connect": ["* bet UMa", "* alf UMa", "* alf UMi"]   // 순서대로 잇는다
"connect": [["a", "b"], ["c", "d"]]                  // 구간 여럿
```

"메라크에서 두베로 선을 긋고 다섯 배 연장하면 북극성" 같은 설명은 선으로
보여줘야 전달된다. 국자 모양을 처음 알려줄 때도 마찬가지다.

### 어떻게 그리는가

엔진의 GeoJSON 레이어를 쓴다. 좌표계는 ICRF(적경/적위, 도)다. 엔진이 선을
그리지 못하므로 **선은 폭이 있는 띠 폴리곤**으로 만든다. 원도 적경/적위
평면이 아니라 3차원에서 그린다 — 평면에서 그리면 천구 극 근처에서 찌그러진다.

엔진이 투영 함수를 밖으로 내주지 않아 DOM 위에 겹쳐 그리는 방법은 쓸 수 없다.
그래서 글자 라벨은 아직 못 넣는다.

## 계절

```jsonc
"months": [3, 4, 5, 6, 7, 8, 9]
```

그 주제가 **초저녁 하늘에 잘 놓이는 달**이다. 8월에 오리온 레슨을 첫 화면에
띄우면 "밖에 나가 확인하라"는 마무리가 공허해진다. 없으면 연중 아무 때나
볼 수 있다는 뜻이다.

지금 볼 수 있는 레슨이 목록 앞으로 온다. **목록에서 빼지는 않는다** — 겨울
레슨을 여름에 읽는 것을 막을 이유는 없다. 철이 아닌 레슨에는 표시가 붙는다.

목록에도 같은 `months` 가 들어가야 포털이 본문을 열지 않고 판단할 수 있다.
`make-lesson-index.mjs` 가 옮겨 주므로 본문에만 적으면 된다.

## 엔진을 다룰 때 알아둘 것

- **객체형 속성은 `null` 로 비워지지 않는다. `0` 을 넣어야 한다.**
  `core.selection = null` 은 아무 일도 일어나지 않는다. 실측으로 확인했다
- `pointAndLock` 은 `core.lock` 을 걸어둔다. 선택만 풀고 잠금을 안 풀면
  화면이 계속 그 천체를 따라다닌다. `director.clearTarget()` 이 둘 다 푼다
- 엔진 객체(`$stel.core.*`)는 **Vue 반응형이 아니다.** 화면에 표시할 값은
  `$store.state.stel.*` 에서 읽어야 한다
- **엔진은 누가 요구하기 전까지 천체를 목록에 올리지 않는다.** 레슨을 여는
  순간 `getObj('Vega')` 는 거의 항상 실패한다. HiPS 타일이 도착하고 처리될
  때까지 재시도해야 한다 (`director.findObj`). 첫 화면에서 별이 0개로 세어지는
  것도 같은 이유이며 고장이 아니다
- **타일은 화면이 그려질 때만 받아온다.** 탭이 숨겨져 있거나 캔버스가 보이지
  않으면 `core.fps` 가 0 이 되고 천체가 영원히 로드되지 않는다. 자동화된
  검사에서 별이 하나도 안 잡히면 데이터를 의심하기 전에 이것부터 보라
- 여러 천체를 찾을 때는 **한꺼번에**(`Promise.all`) 찾는다. 하나씩 기다리면
  못 찾는 천체가 많을 때 재시도 시간이 그 수만큼 곱해진다

## 들어오는 문 두 개

같은 레슨에 두 경로로 닿는다. 서로 대체가 아니라 보완이다.

| 주소 | 무엇 | 엔진 |
|---|---|---|
| `/` | **포털. 사이트의 첫 화면** | **띄우지 않는다** |
| `/sky` | 하늘 | 필요 |
| `/p/learn` | 패널 목록. 하늘을 보다가 고르기 | 이미 떠 있음 |
| `/p/learn/<id>` | 레슨 진행 | 필요 |

포털은 최상위 라우트라 App 밖에서 그려진다. 그래서 WASM 을 내려받지
않는다. 첫 화면에 3MB 를 물리지 않아야 느린 회선과 검색엔진에서 살아남고,
"밤하늘을 읽는 법을 배우는 곳"이라는 정체성이 주소에 드러난다.
레슨을 고르면 그때 하늘이 있는 쪽으로 넘어간다.

`/learn` 은 포털이 거기 있던 시절의 링크라 `/` 로 넘겨준다.
