# 다국어

한국어 · 영어 · 일본어 · 스페인어. 기본은 한국어다.

## 층이 셋인 이유

가용 범위가 서로 달라 따로 다룬다. phet 포털과 같은 구조다.

| 층 | 위치 | 지금 |
|---|---|---|
| UI 문구 | `src/locales/<lang>.json`, `src/plugins/*/locales/<lang>.json` | 4개 언어 전부 |
| 레슨 콘텐츠 | `src/plugins/learn/content/<lang>/` | **4개 언어 전부.** 없으면 ko 로 떨어지고 **화면에 알린다** |
| 천체 이름 | `search-index.json` 의 `k` | ko 191개. 다른 언어는 비어 있으면 원래 식별자를 쓴다 |

콘텐츠가 없을 때 조용히 한국어를 보여주면 사용자는 번역이 끝난 줄 안다.
그래서 레슨에는 안내 문구를 띄우고, 천체 이름은 아예 그 언어 이름이
없으면 원래 식별자(Andromeda Nebula)를 쓴다.

## 주소

언어를 경로에 담는다. 검색엔진이 언어별로 따로 수집하고 캐시도 갈린다.

```
/ko/p/learn/big-dipper
/ja/skysource/Vega
```

**접두어 없는 주소도 받는다.** `/skysource/직녀성` 같은 예전 공유 링크가
살아 있어야 하기 때문이다. 그런 요청은 라우터 가드가 감지한 언어의 주소로
옮긴다. 정규 주소(`canonical`)는 언제나 접두어가 붙은 쪽이다.

언어 결정 순서는 이렇다. 앞의 것이 이긴다.

1. 주소의 접두어 — 공유된 링크는 보낸 사람의 언어를 지켜야 한다
2. 저장된 선택 — 사용자가 직접 고른 적이 있으면 그게 우선
3. 브라우저 언어
4. 한국어

## 화면에서 링크를 걸 때

`to="/p/learn"` 대신 **`:to="$lpath('/p/learn')"`** 를 쓴다. 접두어 없이
걸어도 가드가 고쳐주지만 이동이 한 번 더 생긴다.

## 주의: 경로 접두어를 가정하는 코드

언어를 경로에 넣으면 `path.startsWith('/p/')` 같은 코드가 전부 깨진다.
실제로 사이드 패널이 열리지 않는 문제가 이것 때문이었다. 경로를 볼 때는
반드시 접두어를 떼고 본다.

```js
const bare = this.$langs.splitPath(this.$route.path).rest
```

## 언어를 하나 늘리려면

1. `src/i18n/langs.js` 의 `LANGS` 와 `LANG_NAMES` 에 추가
2. `src/locales/<lang>.json` (56키)
3. `src/plugins/planner/locales/<lang>.json`, `src/plugins/learn/locales/<lang>.json`
4. `src/i18n/meta.json` 에 제목·설명
5. 레슨과 천체 이름은 준비되는 대로. 없어도 동작한다
