## 2. 작업 순서

```bash
cd apps/web-frontend
# … 한 편 옮긴다 …
node tools/check-lesson-parity.mjs en big-dipper   # 원문과 대조한다
node tools/make-lesson-index.mjs                   # 목록을 다시 굽는다
yarn lint
```

말은 [i18n-glossary.md](i18n-glossary.md) 에 고정해 두었습니다. **태그와 화면
문구는 거기서 가져다 씁니다.** 새로 고르지 마세요.

**`index.json` 은 절대 손으로 쓰지 마세요.** 본문에서 구워지는 파일입니다.
순서는 `ko` 에서 물려받으므로 옮긴 차례와 상관없이 목록 순서가 유지됩니다.

**`en` · `ja` · `es` 19편씩을 2026-08-21 에 끝냈습니다. 레슨 번역은 끝났습니다.**
아래는 언어를 더 늘리게 될 때를 위해 남깁니다(6.3 을 먼저 읽으세요).

옮길 때 쓴 순서는 이렇습니다. 그대로 따르기를 권합니다.

1. `big-dipper` 한 편을 **끝까지** 옮기고 화면으로 확인해 형식 문제를 턴다
2. 2~3편씩 묶어 옮기고, 묶음마다 `check-lesson-parity` 로 경고를 하나하나 본다
3. 다 옮긴 뒤 `make-lesson-index` 와 `yarn lint`, 그리고 화면 확인

**옮길 때는 언제나 `ko` 원문에서 직접 옮깁니다.** `en` 을 거쳐 `ja`·`es` 를
만들지 마세요. 오차가 겹칩니다. `en` 은 구조 참고용으로만 씁니다.

### 레슨 파일은 손으로 쓰지 말고 구우세요

```bash
node tools/apply-lesson-translation.mjs ja big-dipper ~/work/ja/big-dipper.mjs
```

옮긴 글만 담은 파일을 주면 **원문을 읽어 옮기는 필드만 갈아끼워** 레슨
파일을 굽습니다. 그러면 `sky`·`show`·성표 식별자를 건드릴 방법이 아예
없습니다. `en` 19편을 그렇게 만들었습니다.

세 번째 인자로 주는 파일은 **작업용이라 저장소에 두지 않습니다.** 저장소에
남는 것은 구워진 `content/<lang>/<id>.json` 하나뿐입니다. 둘 다 두면 JSON 을
고친 뒤 도구를 다시 돌렸을 때 그 수정이 조용히 날아갑니다. 파일 모양은
도구 맨 위 주석에 있습니다.

## 3. 건드릴 것과 건드리면 안 되는 것

한 단계는 이렇게 생겼습니다.

```json
{
  "title":  "국자의 시작, 두베",          ← 옮긴다
  "text":   "<p>… <b>두베</b> …</p>",     ← 옮긴다 (HTML 태그는 그대로 둔다)
  "sky":    { "date": "...", "az": 15, "alt": 50, "fov": 85 },   ← 손대지 않는다
  "show":   { "constellationLines": true },                      ← 손대지 않는다
  "select": "* alf UMa",                                         ← 손대지 않는다
  "highlight": ["Polaris"],                                      ← 손대지 않는다
  "connect":   ["* bet UMa", "* alf UMa"],                       ← 손대지 않는다
  "quiz":   { "q": "...", "opts": [...], "right": 1, "explain": "..." }
}
```

**옮기는 것**: `title` · `subtitle` · `intro` · `tags` · `credits` ·
각 단계의 `title` · `text` · `quiz` 전부.

**옮기지 않는 것**: `id`(파일 이름과 같아야 합니다) · `sky` · `show` ·
`select` · `lookAt` · `highlight` · `connect` · `track` · `level` · `months` ·
`minutes` · `updated`.

특히 **`select` / `highlight` / `connect` 안의 문자열은 사람 말이 아니라 성표
식별자입니다.** `"* alf UMa"` 를 `"Alpha Ursae Majoris"` 로 바꾸면 엔진이 못
찾습니다. `make-lesson-index.mjs` 가 막아주긴 하지만 애초에 건드리지 마세요.

세 가지 함정입니다.

- **HTML 태그** — `<p> <b> <ul> <li> <ol>` 이 본문 안에 있습니다. 그대로 살려야
  합니다. 태그가 깨지면 화면이 통째로 무너집니다
- **`quiz.right` 는 번호입니다** — `opts` 순서를 바꾸면 반드시 함께 고치세요.
  언어에 따라 보기 순서를 바꾸고 싶을 때가 있는데, 그때 제일 잘 틀립니다
- **`tags` 는 포털 검색과 필터가 씁니다** — 옮기되, 같은 개념은 언어 안에서
  같은 말로 통일하세요. 레슨마다 다르게 옮기면 필터가 쪼개집니다

## 4. 이 일이 단순 번역이 아닌 이유

레슨은 **번역이 아니라 다시 쓰기에 가깝습니다.** 세 가지 때문입니다.

### 4.1 숫자와 날짜는 실측값입니다

본문의 고도·방위·시각·각거리는 전부 화면 엔진에서 재서 넣은 값입니다.
"제주에서 4도 안팎", "개기식 01:20~02:30", "10만 년 뒤 6.8도" 같은 것들입니다.
**옮길 때 반올림하거나 어림하지 마세요.** 읽는 사람이 화면에서 바로 대조합니다.

값을 고쳐야 할 것 같으면 고치지 말고 남겨 두세요. 원 세션이 잽니다.

### 4.2 관측지가 박혀 있는 단계가 있습니다

| 레슨 | 고정 관측지 |
|---|---|
| latitude-sky | 시드니(−33.9) · 적도(0) · 제주(33.4) · 북극(89) |
| star-brightness 5 | 제주(33.4, 126.5) |
| twilight | 서울(37.5, 127.0) |
| eclipses 6~7 | 스페인 카디스(36.5, −6.3) |

이건 **의도한 것**입니다. 위도를 비교하는 것이 그 레슨의 주제이기 때문입니다.
그대로 두세요. 나머지 레슨은 관측지를 지정하지 않아 **읽는 사람이 있는 곳의
하늘**이 뜹니다.

다만 본문이 "북위 37도에서는" 처럼 위도로 말하는 곳이 여럿입니다. 스페인어판
독자가 마드리드(40.4°N)라면 대체로 맞고, 남반구 독자에게는 맞지 않습니다.
**남반구 대응은 이번 범위 밖입니다** — `months` 를 위도 부호에 따라 6개월 미는
작업이 필요하고, 그건 앱 세션 몫입니다(handoff-content.md 9장).

### 4.3 한국·동아시아 이야기가 곳곳에 있습니다

28수, 천상열차분야지도, 조선왕조실록, 노인성, 견우와 직녀, 음력 초엿새 …
**19편 전부**에 들어 있습니다.

**빼지 마세요.** 이 프로젝트가 다른 밤하늘 앱과 다른 점입니다. 다만 규칙이
하나 있습니다. 앞 세션에서 세운 것입니다.

> **한국인 관점으로 서술하지 않는다.** "우리 조상들은" (X) → "동아시아에서는" (O).
> "우리나라에서는 안 보인다" (X) → "북위 37도에서는 지평선 위로 올라오지 않는다" (O).

한국어판은 이 규칙에 맞춰 이미 정리해 뒀습니다. **번역할 때 이 구조를 되살리지
마세요.** "In Korea, our ancestors…" 로 옮기면 규칙이 도로 깨집니다.
"In East Asia…", "In Joseon-era Korea…" 처럼 **누구의 이야기인지 밝혀 적는**
방식이 원문의 의도입니다.

반대로, 그 언어권에 **같은 자리를 두고 전해오는 이야기가 따로 있으면 보태는
편이 좋습니다.** 예를 들어 `big-dipper` 6단계는 이미 문화별 이름을 늘어놓는
단계라 스페인어판에 "el Carro" 를 넣을 자리가 있습니다. `moon-phases` 3단계의
달 얼룩도 마찬가지입니다. **더하는 것은 환영, 빼는 것은 신중히.**

## 5. 옮긴 뒤 확인할 것

레슨 한 편을 옮기면 이렇게 봅니다. 앞의 둘은 기계가 봅니다.

1. `node tools/check-lesson-parity.mjs <lang> <id>` — **오류 0.**
   경고는 남아도 되지만 하나하나 이유를 댈 수 있어야 합니다
2. `node tools/make-lesson-index.mjs` 가 오류 없이 끝나는가
   (천체 이름이 깨졌으면 여기서 걸립니다)
3. 포털(`/en`)의 카드 제목·부제·태그가 그 언어로 뜨고, 그 카드에서만
   "아직 한국어" 표시가 사라졌는가
4. 레슨을 열었을 때 **"아직 번역되지 않았다" 안내가 사라졌는가**
5. 단계를 끝까지 넘기며 **글과 화면이 어긋나지 않는가** —
   특히 "붉은 선", "왼쪽 위", "네 번째" 같은 방향·순서 표현
6. 퀴즈를 오답·정답 둘 다 눌러 보고 채점이 맞는가 (`right` 번호)

`check-lesson-parity.mjs` 가 보는 것은 **원문과 어긋나는 것**입니다. 단계 수,
`sky`·`show`·성표 식별자가 원문 그대로인지, HTML 문단 구조가 같은지, 태그가
닫혔는지, 본문 숫자가 같은지, 옮기다 만 한국어가 남았는지, 퀴즈 보기 개수와
`right` 범위입니다. **눈으로 볼 수 없는 것을 봅니다.** 5·6번만 사람 몫입니다.

### 숫자 경고는 대부분 정상입니다

오류는 세 언어 모두 0, 경고는 `en` 90건 · `ja` 36건 · `es` 91건인데 **전부
표기 방식 차이**였습니다. 갈래가 넷뿐이니 여기 해당하면 넘어가도 됩니다.

| 갈래 | 예 |
|---|---|
| 달 이름 (en·es) | `8월 13일` → `13 August` (8이 사라짐) |
| 만·천 단위 | `2만 6천 광년` → `26,000 light years` · `2万6000光年` |
| 말로 쓰는 수 (en·es) | `1년에` → `a year` · `1위` → `first` · `50분의 1` → `one fiftieth` |
| **한자 숫자 (ja)** | `28수` → `二十八宿` · `1년에` → `一年に` · `2천 년` → `二千年` |

일본어는 **월·일과 실측값에 아라비아 숫자를 그대로 쓰므로 경고가 영어의
절반 이하**입니다. 남는 것은 거의 한자 수사뿐입니다. 스페인어는 영어와 같은
갈래에 세기 표기(`19세기` → `el siglo XIX`)가 하나 더 붙습니다.

**이 갈래에 들어맞지 않는 경고는 진짜입니다.** 실제로 `seasons` 7단계에서
원문의 `28수` 두 번 중 하나를 "twenty-eight" 로 풀어 써 값이 사라진 것을
이 검사가 잡았습니다.

전체 점검 항목은 [docs/lesson-review.md](lesson-review.md) 에 있습니다.
한국어판 검수에 썼던 것인데, 3장(사실 확인)은 건너뛰고 4~6장만 보면 됩니다.

**세 언어를 사람이 검수할 때는 [docs/i18n-review.md](i18n-review.md) 를 쓰세요.**
기계가 이미 본 것과 원리적으로 못 보는 것을 갈라 놓았습니다. 못 보는 것이
넷입니다 — 퀴즈 보기의 뜻, 화면을 가리키는 말, **번역하며 새로 들어온 사실
주장**, 숫자에 붙은 단위입니다.

## 6. 남은 일

레슨 번역이 끝났으므로, 다음 세션의 일은 이 세 가지입니다. **6.1 과 6.2 는
같은 파일을 고치니 한 번에 하세요.**

### 6.1 천체의 현지 이름 (다음 세션의 주 과제)

`public/search-index.json` 의 `k` 항목입니다. 지금 `ko` 만 191개 들어 있고
(`apps/search-index/korean-names.json` 에서 옵니다), 다른 언어는 비어 있어
**검색창에서 원래 식별자로만 찾힙니다.**

레슨이 여러 곳에서 "검색창에 이름을 넣어 보세요" 라고 시키므로, 이게 없으면
그 안내가 반쪽이 됩니다. 일본어는 특히 아쉽습니다(こと座のベガ 등).

`korean-names.json` 과 같은 모양으로 언어별 파일을 만들고
`apps/search-index/build_index.py` 가 함께 읽도록 고치면 됩니다.
`k` 는 이미 `{'ko': [...]}` 꼴의 언어별 dict 라 **구조를 바꿀 필요가 없습니다.**

말은 [i18n-glossary.md](i18n-glossary.md) 2장 태그 대역표에 이미 상당수
들어 있습니다(`북두칠성` → `el Carro` / `北斗七星`, `좀생이별` → `las Cabrillas`
/ `すばる` 등). 거기서 가져다 쓰면 레슨 본문과 검색창의 말이 어긋나지 않습니다.

### 6.2 유성우가 검색되지 않는 것 (앱 세션 몫)

`build_index.py` 가 `skydata/meteor-showers.json` 을 훑지 않아 유성우가
색인에 하나도 없습니다. 6.1을 하게 되면 같은 파일을 고치게 되니 **한 번에
처리하는 편이 쌉니다.** 자세한 것은 handoff-content.md 4장.

### 6.3 언어를 더 늘릴 것인가

늘리는 절차는 i18n.md 마지막 장에 있습니다. 다만 **레슨 본문이 언어 수만큼
불어납니다**(언어당 약 7만 자, 지금 네 언어 합쳐 약 28만 자). 한 언어를 더
늘리면 UI 168키에 더해 레슨 19편을 새로 옮겨야 하고, **그 뒤로 한국어판을
고칠 때마다 다섯 곳을 함께 고쳐야 합니다.**

늘리기 전에 이것부터 정하기를 권합니다. **한국어판 본문이 바뀌면 다른
언어를 어떻게 따라가게 할 것인가.** 지금은 방법이 없습니다.
`check-lesson-parity.mjs` 가 단계 수와 문단 구조가 어긋난 것은 잡지만,
한국어 문장만 고친 경우는 잡지 못합니다. 레슨별로 원문의 갱신일을 번역본에
적어 두고 대조하는 정도가 가장 싼 방법일 것입니다.

### 6.4 스페인어판 독자가 어디 있는가 (검수가 새로 짚은 것)

**지금 스페인어판은 사실상 북위 33~40도 독자를 위한 판입니다.** 그 언어를
쓰는 사람의 다수는 거기 없습니다 — 멕시코시티 19.4°N, 보고타 4.7°N,
리마 −12°, 산티아고 −33.4°, 부에노스아이레스 −34.6°.

문제가 "화면이 틀린다"로 나타나지 않는 것이 고약합니다. **19편 중 위도를
박아 둔 것은 4편뿐**이고(`star-brightness` 5 · `latitude-sky` 3·4·5·7 ·
`eclipses` 4 · `twilight` 1) 나머지 15편은 `sky.lat` 이 비어 있어 **독자가
있는 곳의 하늘이 그려집니다.** 그래서 **화면은 독자의 하늘인데 글이 남의
하늘을 설명합니다.** 독자는 자기가 뭘 잘못했는지 알 수 없습니다.

검수가 심한 순서로 정리해 두었습니다([i18n-review-result.md](i18n-review-result.md) 3장).
요약하면 이렇습니다.

| | 편수 | 무엇을 해야 하나 |
|---|---|---|
| 남반구에서 사실상 못 읽힘 | 6편 | `polaris-changes` 전편 · `big-dipper` 1·7·8·9 · `latitude-sky` 1~2 — 북극성과 국자가 지평선 아래입니다. **구조를 손대야 합니다** |
| 계절만 뒤집으면 됨 | 5편 | `seasons` · `spring-arc` · `summer-triangle` · `orion-nebula` · `pleiades`. `index.json` 의 `months` 도 함께 |
| 문장 몇 줄 | 4편 | 8.0 에서 셋(`variable-stars` 7 · `latitude-sky` 5 · `star-brightness` 4)은 고쳤습니다. 남은 것은 `eclipses` 9 의 **중남미 독자용 "다음 기회"** 입니다 |

**중남미용 일식 항목이 남은 숙제입니다.** 스페인 것 하나(2026-08-12)가
지나면서 그 단계가 더 얇아졌습니다. 넣으려면 **일식 날짜와 통과 지역을
검증할 수 있어야 합니다** — 레슨에 박히는 날짜라 어림으로 넣으면 안 됩니다.
`eclipses` 4~6단계가 이미 관측지를 옮겨 다니므로 자리는 있습니다.

남반구 대응은 `months` 를 위도 부호에 따라 6개월 미는 작업이 앞서야 하고
그건 앱 세션 몫입니다(handoff-content.md 9장). **다만 그것만으로는 위 6편이
해결되지 않습니다.** `latitude-sky` 가 관측지를 옮겨 다니도록 이미 만들어져
있으니 뼈대는 그쪽에 있습니다.

> **셋 다 어긋나 있었습니다.** 화면 문구를 용어집에 올릴 때는 로케일에
> 실제로 있는지 확인하고 올리세요.

말을 새로 고정한 것이 둘입니다. **용어집에 반영했습니다.**

- **`el Boyero` 는 목동자리(Boötes) 전용입니다.** 설화의 견우까지 이 말로
  옮겨 놓아 한 낱말이 두 천체를 가리키고 있었습니다. `summer-triangle` 6 의
  「El Boyero y la Tejedora se miran a través de la Vía Láctea」 는 목동자리로
  읽으면 은하수 근처에 있지도 않은 별자리 이야기가 됩니다. 포털 카드의
  부제와 태그에까지 나가 있었습니다. **견우 → `el Vaquero`** 로 바꿨습니다
- **북두칠성 몸통은 `el cuenco`** 입니다. `la cuchara`(숟가락)가 `el cazo`(국자)와
  나란히 놓여 서로 다른 물건 둘로 읽혔습니다(10곳)

일본어에서 고친 것 셋입니다. 셋 다 한 문장짜리였습니다.

- **`polaris-changes` 9 · `seasons` 7 해설** — 황도 12궁 한 자리(30도)를
  「ひと宿」 라 적었습니다. 宿 은 28수의 하나라 약 12.9도입니다. 게다가
  `polaris-changes` 9 는 **바로 앞 문장**이 「約30度、星座ひとつぶん」 이라
  스스로 모순됐습니다. 같은 판이 `moon-phases` 7 과 `seasons` 7 본문에서는
  「月が一日にひと宿ずつ」 로 **올바르게** 쓰고 있어 더 위험했습니다
- **`proper-motion` 6** — 「事実上の恒星でした」. 원문 '붙박이'를 恒星(붙박이별)로
  옮겨 뜻이 사라졌습니다 → 「事実上動いていません」
- **`twilight` 6** — 북위 33~38도를 「本州」 로 넓혔습니다. 혼슈 북단은
  41.5도입니다 → 「日本の南部」

**읽는 사람이 어디 있는가**로 걸린 것 넷입니다. 번역이 정확해도 생깁니다.

- `variable-stars` 7 (`en`·`es`) — 알골 극소를 **한국 시각**으로 줬습니다.
  한국의 저녁은 스페인에서 낮입니다. **UTC 로 바꾸고 2.87일씩 옮겨 자기
  저녁에 걸리는 날을 찾으라**고 고쳤습니다. `ja` 는 JST=KST 라 원래부터
  「日本の夜」 로 맞게 되어 있었습니다
- `eclipses` 9 (`es`) — **2026-08-12 개기일식을 "코앞"이라 적었는데 이미
  지났습니다.** 2027-08-02 만 남겼습니다
- `latitude-sky` 5 (`es`) — 남반구를 '저쪽 사람들'로 불렀습니다. 스페인어

- `star-brightness` 4 (`ko`·`en`) — 아케르나르를 "한국에서는" 으로 적어
  `ja`·`es` 와 어긋나 있었습니다 → **네 언어 모두 북위 33도**로 맞췄습니다

### 8.1 번역 준비로 고친 것

### 8.2 영어판·일본어판·스페인어판 (2026-08-21)

**세 언어 모두 19편 · 162단계 · 퀴즈 38개를 다 옮겼습니다. 레슨 번역이
끝났습니다.** 대조 검사 오류 0(경고는 위 5장의 표기 차이). 세 언어 모두
`ko` 와 대조해 확인했습니다.

- 편수 19, 총 단계 162, 목록 순서 동일
- 비번역 필드(`id` `minutes` `level` `track` `months` `steps`) 불일치 0
- 짚는 천체 72개로 `ko` 와 같음
- 고유 태그 67개로 `ko` 와 같고, 되풀이되는 태그의 개수까지 같음
  (`북극성` 3 → `Polaris` 3 / `北極星` 3 / `Polaris` 3 …)
- 포털 카드 19장에 "아직 한국어" 표시 0, 레슨 19편 모두 안내문 사라짐

영어는 **영국식 철자**로 통일했습니다(`colour`). 일본어는 **です・ます체**,
스페인어는 **tú 기준**입니다. 말은 [i18n-glossary.md](i18n-glossary.md) 에 있습니다.

그 언어권에 같은 자리를 두고 전해오는 것은 **보탰습니다.** 몇 가지 예입니다.

- `big-dipper` 6단계 — 문화별 이름 목록에 일본을 넣었습니다(`日本・韓国・中国`)
- `pleiades` 3단계 — 일본어판은 `すばる` 를 목록 맨 앞에 놓았습니다
- `eclipses` 9단계 — 2035년 개기일식이 **일본 노토반도~북간토를 지납니다.**
  일본어판에 그 사실을 넣었습니다
- `star-distance` 9단계 — "삼국시대·조선 시대"를 일본어판에서는 `飛鳥時代`·
  `江戸時代` 로 옮겼습니다. 빛이 출발한 때를 읽는 사람의 역사로 짚는 대목이라
  나라를 바꿔 적는 것이 원문의 의도에 맞습니다
- `star-brightness` 4단계 — 아케르나르를 "한국에서는 안 보인다" 대신
  **`북위 33도보다 북쪽에서는 보이지 않는다`** 로 바꿨습니다(3장 위도 규칙)
- `orion-nebula` 1단계 — 스페인어판에 <b>las Tres Marías</b>(오리온 허리띠의
  스페인어권 이름)를 넣었습니다
- `pleiades` — 스페인어판 제목과 태그를 `las Cabrillas` 로 했습니다
- `eclipses` 9단계 — 스페인어판에 **2026-08-12 개기일식이 스페인 북부를,
  2027-08-02 개기일식(이 레슨이 이미 보여주는 그것)이 남부를 지난다**는
  사실을 넣었습니다. 스페인 독자에게는 이쪽이 훨씬 가까운 기회입니다
- `star-distance` 9단계 — 빛이 출발한 때를 읽는 사람의 역사로 짚는 대목이라
  나라를 바꿔 적었습니다. `삼국시대`·`조선` → ja `飛鳥時代`·`江戸時代`,
  es `visigodos`·`Siglo de Oro`
