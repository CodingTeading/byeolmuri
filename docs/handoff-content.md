## 1. 이 프로젝트가 무엇인가

**별무리** — 밤하늘을 읽는 법을 배우는 비영리 오픈소스 사이트.

- 라이브: <https://byeolmuri.codingteading.com>
- 저장소: <https://github.com/CodingTeading/byeolmuri> (AGPL-3.0)
- [Stellarium Web Engine](https://github.com/Stellarium/stellarium-web-engine) 기반.
  Stellarium 공식 프로젝트와는 무관한 별개 프로젝트

원본과의 차이는 셋입니다. **오늘 밤 관측 플래너**, **이론과 실습을 한 화면에**,
**한국어 우선 4개 언어**. 광고도 추적도 없고 백엔드도 없습니다.

## 2. 학습 화면이 어떻게 생겼나

왼쪽에 **진짜 하늘**이 계속 떠 있고, 오른쪽 패널에서 설명이 진행됩니다.
**설명이 한 단계 넘어갈 때마다 하늘이 그에 맞춰 움직입니다.** 시야가 옮겨가고,
확대되고, 별자리 그림이 켜지고, 시간이 400배로 흐릅니다.

천문대에서 선생님이 돔을 돌려가며 설명하는 것과 같은 구성입니다. 동영상 강의와
다른 점은 **하늘이 살아 있다**는 것입니다. 학생은 설명 도중에도 직접 끌어서
돌려보고 다른 별을 눌러볼 수 있습니다.

좁은 화면(760px 이하)에서는 하늘이 위, 설명이 아래로 나뉩니다.

## 3. 레슨을 어떻게 만드나

**코드를 건드릴 필요가 없습니다.** 파일 두 개만 만지면 됩니다.

```
apps/web-frontend/src/plugins/learn/content/ko/<id>.json   레슨을 쓴다
node tools/make-lesson-index.mjs                           목록을 다시 굽는다
```

`index.json` 은 손으로 고치지 않습니다. 본문에서 굽습니다. 목록과 본문이
어긋나면 겨울 레슨이 여름 첫 화면에 올라옵니다.

**형식·문법·주의사항은 반드시 이 문서를 먼저 읽으세요:**
[apps/web-frontend/src/plugins/learn/README.md](../apps/web-frontend/src/plugins/learn/README.md)

본보기는 `content/ko/big-dipper.json` — 9단계, 퀴즈 2개짜리 완성된 레슨입니다.
레슨 머리에는 `level`(intro·basic·deep), `track`(principle·target·measure),
`months` 가 들어갑니다. **level 과 track 은 열쇳말이라 한국어를 그대로 적으면
안 됩니다.** 표시할 이름은 `locales/<lang>.json` 에 있습니다.

### 한 단계는 이렇게 생겼습니다

```jsonc
{
  "title": "북두칠성은 별자리가 아닙니다",
  "text": "<p>별자리 그림을 켜 보겠습니다...</p>",
  "sky":  { "fov": 90 },                       // 적은 것만 바뀐다
  "show": { "constellationArt": true },        // 나머지는 이전 단계 유지
  "select": "CON western UMa",
  "quiz": { "q": "...", "opts": [...], "right": 1, "explain": "..." }
}
```

### 하늘에 표시할 수 있습니다

"이 별을 보세요" 라고 쓰는 것과 실제로 짚어주는 것은 다릅니다.

```jsonc
"highlight": ["* alf UMa", { "target": "* 80 UMa", "radius": 0.07 }],
"connect":   ["* bet UMa", "* alf UMa", "* alf UMi"]
```

`highlight` 는 동그라미, `connect` 는 순서대로 잇는 선입니다. 원 크기는 시야에
맞춰 자동으로 정해지고 사용자가 확대·축소해도 따라갑니다. 가까이 붙은 두 별은
`radius` 를 직접 주세요. 자세한 것은 learn/README.md.

글자 라벨은 아직 못 넣습니다. 엔진이 투영 함수를 내주지 않아서입니다.

### 계절

```jsonc
"months": [3, 4, 5, 6, 7, 8, 9]
```

그 주제가 초저녁 하늘에 잘 놓이는 달입니다. 지금 볼 수 있는 레슨이 목록 앞으로
오고, 철이 아닌 것에는 표시가 붙습니다. **목록에서 빼지는 않습니다.**
`index.json` 의 항목에도 같은 `months` 를 넣어야 포털이 본문을 열지 않고
판단할 수 있습니다.

### 꼭 지킬 것

- **위치는 되도록 지정하지 않습니다.** 사용자가 있는 곳의 하늘이어야 오늘 밤
  밖에 나가 그대로 확인할 수 있습니다. 위도를 비교하는 레슨처럼 꼭 필요할 때만
  `lat`/`lng` 를 씁니다
- **마지막 단계는 밖에서 직접 해볼 것으로 맺습니다.** 화면 안에서 끝나면
  플라네타리움이지 관측 교육이 아닙니다
- 퀴즈 해설에는 정답만이 아니라 **왜 다른 보기가 틀렸는지**를 넣습니다
- 별 이름의 유래, 문화별 이름 같은 이야기는 기억에 오래 남습니다.
  **모든 레슨에 하나씩** 넣되, 그것이 레슨의 뼈대가 되어서는 안 됩니다

### 천체 이름

엔진이 아는 이름이어야 합니다. 검색창에 쳐서 나오면 쓸 수 있습니다.
확실하지 않으면 `apps/web-frontend/public/search-index.json` 에서 확인하세요.
고유명이 없는 별도 있습니다 — 미자르는 `Mizar` 가 아니라 `* zet UMa` 입니다.

## 4. 레슨을 어떤 기준으로 나누나

축은 난이도도 테마도 아니라 **질문**입니다. 우리 매체가 남들보다 잘하는 건
셋입니다 — 시간을 돌리고, 위치를 옮기고, 그게 지금 머리 위 진짜 하늘이라는 것.
**그 셋으로만 답할 수 있는 질문**이 좋은 레슨입니다. 나머지는 위키백과가 더
잘합니다.

세 갈래로 나눕니다.

| 갈래 | 성격 | 예 |
|---|---|---|
| **원리** | 시간을 돌려야 답이 나오는 것 | 계절마다 별자리가 바뀌는 이유 · 달의 위상 · 행성의 역행 · 남반구의 하늘 |
| **대상** | 실제로 찾아볼 수 있는 것 | 여름 대삼각형 · 오리온성운 · 안드로메다은하 · 알비레오 |
| **측정** | 우리가 어떻게 알아냈나 | 별의 밝기란 무엇인가 · 별까지 거리 재기 · 별의 색과 온도 |

**"순위" 형식도 좋습니다** — 가장 밝은 별 top 10, 가장 가까운 별 같은 것.
위키백과와 다른 점은 **그 별들을 직접 눈으로 보여준다**는 것입니다. 다만 목록에서
그치지 말고 "왜 저것이 가장 밝은가" 같은 질문으로 이어가면 훨씬 강해집니다.

**한국 콘텐츠는 별도 갈래로 두지 않습니다.** 천상열차분야지도, 28수, 견우직녀는
각 레슨 안에 녹입니다. 따로 빼면 부록처럼 보이는데, 한국 콘텐츠는 우리
정체성이라 부록이 되면 안 됩니다.

### 이 매체에서 약한 주제

**블랙홀과 먼 은하는 피하세요.** 데이터에 AGN 161개, 세이퍼트은하 239개가 있지만
화면에서는 전부 점이고 블랙홀은 아예 보이지 않습니다. "화살표가 가리키는 빈 곳을
보며 글 읽기"가 되는데, 그건 위키백과보다 못한 경험입니다. 은하는
안드로메다·삼각형자리·M81 정도까지가 한계입니다.

쓸 수 있는 소재의 규모는 이렇습니다.

```
고유명 있는 천체     405개
6등급 이내 DSO        83개   (맨눈~쌍안경)
10등급 이내 DSO      541개   (소형 망원경)
항성                15,527개 (7등급까지)
별자리                 88개
```

### 다음에 쓸 만한 것

19편이 채워졌습니다(아래 10번). 엔진 쪽에서 고유운동을 살리고 유성우 데이터를
넣어 준 덕에 세 편이 새로 가능해져 바로 만들었습니다. 남은 자리는 이렇습니다.

- **대상** 갈래 — *겨울 대육각형* · *이중성단과 페르세우스* · *구상성단 M 13*
- **원리** — *조석과 달* · *왜 하늘은 파랗고 노을은 붉은가*(대기 모듈이 있으니
  화면으로 보여줄 수 있습니다)
- **측정** — *하늘의 각도를 재는 법*(주먹 10도·육분의) · *별의 나이는 어떻게 아나*
- 레슨끼리 잇는 고리를 본문에 심어 두었습니다. 새 레슨을 쓸 때 기존 레슨을 한 번씩
  가리키면 포털이 목록이 아니라 길처럼 읽힙니다

### 앱·엔진 세션에 부탁드릴 것

1. **먼 미래에서 렌더러가 멈춥니다.** 서기 <b>10만 년</b>까지는 60fps 로 멀쩡한데
   <b>15만 년</b> 언저리에서 화면이 굳고 페이지가 응답하지 않습니다(과거는 기원전
   4000년까지 정상). 지금은 '별자리는 영원하지 않다' 레슨을 10만 년에서 끊어
   피해 갑니다. 위성 궤도 전파나 소행성 궤도 계산이 발산하는 쪽이 의심됩니다.
2. **알골 극소 시각을 플래너에** — 변광성 레슨을 밖으로 내보내는 마무리가
   "오늘 알골 극소는 21:47" 한 줄로 크게 좋아집니다. 주기 2.867일에 기준 시각만
   있으면 되는 계산입니다.
3. **유성우 극대일을 '오늘 밤' 탭에** — 복사점 데이터는 이미 들어와 있으니,
   극대일 앞뒤로 "오늘은 페르세우스자리 유성우 극대" 한 줄이면 충분합니다.

### 엔진으로 되는 것과 안 되는 것 (실측)

레슨을 기획하기 전에 확인해 둔 것들입니다. 되는 쪽은 그대로 소재가 되고,
안 되는 쪽은 아무리 좋은 주제라도 글로만 남습니다.

○ 는 그대로 쓸 수 있고, △ 는 되는 범위가 좁으며, ✕ 는 엔진을 고쳐야 합니다.

| 되는가 | 무엇 |
|---|---|
| ○ | **세차운동** — 기원전 4000년부터 서기 15000년까지 천구 북극이 실제로 옮겨 다닙니다 |
| ○ | **월식** — 개기월식의 붉은 달이 그대로 그려집니다 |
| ○ | **일식의 부분식** — 달의 검은 원반이 태양을 베어 뭅니다 |
| ○ | **행성의 역행** — 별에 시야를 묶고 시간을 흘리면 고리를 그립니다 |
| ○ | **박명** — 일몰부터 천문박명까지 하늘색이 단계별로 바뀝니다 |
| ○ | **고유운동** — 수만 년을 돌리면 북두칠성 국자가 실제로 휩니다 |
| △ | **유성우** — 복사점과 극대일은 나오지만 유성이 그쪽에서 쏟아지지는 않습니다 |
| ✕ | **개기일식의 코로나** — 완전히 가려지면 화면은 새까맣습니다 |
| ✕ | **변광성** — 알골도 미라도 밝기가 고정입니다 |

#### 고유운동 (2026-08 에 됨)

엔진은 원래부터 고유운동을 적용하고 있었습니다 (`stars.c` 의
`star_get_astrom` 이 `위치 + 속도 × 경과시간` 으로 계산합니다). 안 보였던 이유는
**데이터가 비어 있었기** 때문입니다 — 별 15,527개 중 시차는 15,409개가 들어
있는데 `pra`/`pde` 는 전부 0 이었습니다.

HYG 항성 목록에서 값을 채워 넣었습니다. 우리 별은 전부 HIP 번호를 갖고 있어
매칭이 확실합니다. 도구는 `apps/skydata-tools/add_proper_motion.py`.

시차가 없는 별 118개는 여전히 안 움직입니다. 엔진이 시차 없는 별의 고유운동을
일부러 무시합니다 — 속도가 무한대가 되기 때문입니다 (`stars.c:113`).

**"10만 년 뒤 북두칠성"** 레슨을 쓸 수 있습니다. 북두칠성 레슨의 후속편으로
자연스럽습니다. 실제로 10만 년을 돌리면 일곱 별이 각각 2.4°~4.0° 움직이고,
방향이 서로 달라 국자가 벌어집니다 — 두베는 서쪽으로, 메라크는 동쪽으로.

주의할 데이터 오류가 하나 있습니다. 업스트림에서 **세타 큰곰자리(HIP 46853)에
`* eta UMa` 가 잘못 붙어 있습니다.** 알카이드는 HIP 67301 입니다. 알카이드를
가리킬 때는 고유명 `Alkaid` 를 쓰세요.

#### 변광성과 코로나를 하지 않는 이유

**변광성** — `stars.c` 에 변광 관련 코드가 한 줄도 없습니다. 밝기는 타일에 박힌
고정값입니다. 제대로 하려면 주기·진폭·기준시각을 별 타일 스키마에 넣고 매 프레임
등급을 다시 계산해야 합니다. 데이터도 GCVS 같은 변광성 목록이 필요합니다.
**엔진 포크가 깊어지는 쪽**이라 업스트림을 따라가기가 어려워집니다.

대신 **레슨 설계로 우회하는 편이 낫습니다.** 알골은 2.87일 주기로 2.1등급과
3.4등급을 오갑니다. 화면에서 밝기가 안 변해도, 알골과 비교별을 나란히 짚고
"오늘 밤 몇 시에 나가서 둘을 비교해 보세요" 로 맺으면 됩니다. 오히려 밖으로
내보내는 레슨이 됩니다. 극소 시각 계산은 간단하니 플래너에 "오늘 알골 극소
21:47" 같은 항목을 넣는 것이 비용 대비 효과가 큽니다.

**개기일식 코로나** — 부분식은 이미 잘 됩니다. 달의 검은 원반이 태양을 베어
물고, 대기 모듈이 일식 감광까지 계산합니다 (`atmosphere.c` 의 `eclipse_factor`).
하지만 코로나를 그리는 코드는 없어서 완전히 가려지면 검은 원반만 남습니다.

`marks` 레이어로 태양 자리에 흰 고리를 그리는 우회가 가능하긴 합니다. 그런데
코로나는 불규칙하게 뻗는 부드러운 빛이라 납작한 고리로는 조잡합니다.
**어설픈 가짜보다 "여기서는 검게만 보이지만 실제로는 이렇습니다" 라며 사진을
곁들이는 편이 정직하고 교육적입니다.** 하지 않기로 했습니다.

#### 사진 겹치기(DSS) — 됩니다 (2026-08 붙임)

`show: { "dss": true }` 로 실제 촬영 사진을 하늘 위에 겹칠 수 있습니다.
쓰는 단계는 andromeda 5 · orion-nebula 4·6 · pleiades 6 넷입니다.

한동안 동작하지 않았습니다. `App.vue` 의 데이터 소스 등록 블록에
`core.dss.addDataSource(...)` 가 빠져 있었기 때문입니다. 2026-08 검수에서
찾아 넣었습니다.

```js
core.dss.addDataSource({ url: 'https://alasky.cds.unistra.fr/DSS/DSSColor' })
```

**이것 하나만 우리 서버 밖에서 받아옵니다.** CDS(스트라스부르 천문자료센터)의
공개 HiPS 서베이입니다. 판자 사진을 통째로 담고 있어 우리가 안고 있기에는 너무
큽니다. 감사문은 `data-credits-dialog.vue` 에 이미 들어 있습니다.

주의할 것 둘입니다.

- **회선을 탑니다.** 타일이 도착하기까지 잠깐 걸리므로, 사진을 쓰는 단계는
  바로 앞 단계에서 같은 자리를 이미 보고 있게 두는 편이 낫습니다
- **끄는 것을 잊지 마세요.** 다음 단계에서 `"dss": false` 를 주지 않으면
  사진이 계속 깔려 있습니다 (orion-nebula 7 이 그 예입니다)

#### 유성우 — 되는 만큼만 (2026-08)

유성우 11개를 넣었습니다 (`apps/skydata-overlay/meteor-showers.json`).
사분의·거문고·페르세우스·오리온·쌍둥이 등 한국에서 볼 만한 것들입니다.

**되는 것** — 극대일·활동 기간·ZHR·진입 속도가 엔진 안에 들어옵니다. 레슨에서는
`highlight` 에 `{ra, de}` 로 복사점 좌표를 직접 적어 동그라미를 칩니다.

**검색은 안 됩니다** (2026-08 확인). 화면 위 검색창은 엔진에 묻지 않고
`public/search-index.json` 이라는 정적 파일만 봅니다. 그 파일의 24,845개 안에
유성우가 **하나도 없어서** '페르세우스자리 유성우' 도 'Perseid' 도 결과가
비어 있습니다. 엔진 쪽에는 `meteor-shower` 객체가 `NAME <designation>` 으로
등록되어 있으니(`modules/meteors.c` 의 `shower_get_designations`),
`apps/search-index/build_index.py` 가 `skydata/meteor-showers.json` 도 함께
훑도록 고치면 됩니다. 앱 세션 몫입니다.

**안 되는 것** — 유성이 복사점에서 쏟아지지 않습니다. 엔진의 유성 생성은
모듈 전역 `zhr` 하나만 보고 방향을 완전히 무작위로 잡습니다. 유성우별 `zhr` 과
복사점은 유성 생성에 **쓰이지 않습니다** (`modules/meteors.c` 의
`meteors_update` 와 `meteor_create`). 산발 유성은 지금도 시간당 10개 떨어집니다.

그래서 레슨에서 `zhr` 을 올려 유성을 쏟아지게 하는 것은 **권하지 않습니다.**
방향이 제멋대로라 유성우의 핵심인 "한 점에서 퍼져 나온다"를 오히려 반대로
가르치게 됩니다. 복사점을 짚고 "이 점에서 퍼져 나오는 것처럼 보입니다" 라고
설명한 뒤 실제 관측으로 넘기는 편이 정직합니다.

제대로 하려면 C 코드를 고쳐야 합니다 (활동 중인 유성우를 골라 그 복사점에서
유성을 만들기). `meteors_update` 와 `meteor_create` 에 40줄쯤 되는 작업이고,
WASM 재빌드가 필요합니다. 앱 세션에 요청하세요.

## 5. 포털

레슨은 고정된 교과서가 아니라 **계속 늘어나는 포스트**입니다. 포털은 그 목록을
보여주는 화면이자 **사이트의 첫 화면**입니다.

```
/            포털 — 엔진(3MB WASM)을 띄우지 않는다. 가볍고 검색에 잘 잡힌다
/sky         하늘
/learn       옛 포털 주소. / 로 넘겨준다
/p/learn     패널 목록 — 하늘을 보다가 고르기
/p/learn/<id>  레슨 진행
```

파일은 `apps/web-frontend/src/plugins/learn/portal.vue` 입니다. 최상위 라우트라
App 밖에서 그려집니다 — 그래서 엔진이 로드되지 않습니다. **이 성질을 깨뜨리지
마세요.** 포털에서 `$stel` 을 쓰면 안 됩니다. 배경의 별하늘도 엔진이 아니라
CSS 로 그린 것입니다.

지금 들어 있는 것: 갈래별 묶어 보기 · 계절 우선 정렬과 "오늘 밤 볼 수 있는
레슨" · 제목·태그 검색 · 갈래/계절 필터 · 언어 전환 · 4개 언어 문구.

### 포털에 앞으로 필요한 것

- 레슨이 30편을 넘으면 태그 페이지(`/t/<태그>`)와 페이지 나누기
- 레슨 상세를 엔진 없이 미리 보여주는 소개 페이지 — 지금은 카드를 누르면
  바로 엔진이 뜹니다. 검색에서 들어온 사람에게는 무거울 수 있습니다
- 진행률 표시 (저장은 앱 쪽 일입니다. 9번 참고)
- 구조화 데이터(JSON-LD `Course`)로 검색 결과에 단계 수·소요 시간 노출

## 6. 다국어

레슨은 `content/<lang>/` 로 나뉩니다. 지금은 `ko` 만 있고, 없는 언어는 한국어로
떨어지면서 **화면에 그 사실을 알립니다.** 조용히 한국어를 보여주면 사용자는
번역이 끝난 줄 압니다.

화면 문구는 `src/plugins/learn/locales/<lang>.json` 에 넣습니다. 한국어를 코드에
직접 쓰지 마세요. 자세한 것은 [docs/i18n.md](i18n.md).

**레슨을 옮기는 일 자체는 [docs/handoff-i18n.md](handoff-i18n.md) 에 따로
정리했습니다.** 단순 번역이 아니라 다시 쓰기에 가까운 이유와, 손대면 안 되는
필드가 적혀 있습니다.

**링크를 걸 때는 `to="/p/learn"` 대신 `:to="$lpath('/p/learn')"`** 를 씁니다.
주소에 언어가 들어가기 때문입니다.

## 9. 앱 쪽에 요청할 일

레슨을 쓰다 보면 지금 형식으로 안 되는 것이 나올 수 있습니다. 아래는 앱 세션에
요청하면 되는 것들입니다. 직접 고치지 마세요.

- 표시에 **글자 라벨** 붙이기 (엔진이 투영 함수를 내주지 않아 아직 못 함)
- 화살표 머리, 점선 같은 다른 표시 모양
- 단계마다 배경음이나 애니메이션
- 레슨 진행률 저장
- 새로운 `show` 항목 (director.js 의 TOGGLES 에 추가해야 함)
- 남반구 계절 대응 (`months` 를 위도 부호에 따라 6개월 밀기)

2026-08 검수에서 나온, **앱 세션이 판단해야 하는 것 둘**입니다.

1. **검색 색인에 유성우** — `build_index.py` 가 `meteor-showers.json` 을 훑지
   않아 유성우가 검색되지 않습니다 (4장 참고)
2. **패널 닫기 버튼** — `observing-panel-root-toolbar.vue` 가 잘 만들어져 있으나
   어디에서도 import 되지 않는 죽은 코드입니다. `observing-panel.vue` 에는
   툴바가 없어 화면에 × 버튼이 아예 없습니다. 곁들여 패널 탭 링크가
   `$lpath()` 없이 raw path 를 써서 `href` 에 언어 접두어가 빠집니다
   (클릭은 정상, 새 탭으로 열기·크롤러에만 영향)

한 가지는 콘텐츠 쪽에서 먼저 고쳤습니다. `director` 가 레슨에 들어올 때의
하늘(위치·시각·시간 배속·시야·표시 항목)을 적어 두고 나갈 때 되돌립니다.
위도를 비교하는 레슨이 관측지를 적도로 옮겨 놓고 나가면 앱이 계속 남의 동네
하늘을 보여주기 때문입니다.

반대로 **레슨 JSON 과 포털 화면은 마음껏 바꾸셔도 됩니다.**
