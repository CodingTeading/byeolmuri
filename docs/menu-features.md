# 왼쪽 위 메뉴의 기능들

2026-08-22 에 세 가지를 더했습니다. 그전까지 메뉴에는 **「보기 설정」과
「오늘 밤의 행성」 둘뿐**이었습니다.

| 메뉴 | 무엇 | 파일 |
|---|---|---|
| 하늘 밝기 | 사는 곳의 광공해를 골라 화면을 그만큼만 보여준다 | `assets/sky-brightness.js` · `components/sky-brightness-dialog.vue` |
| 이번 달 볼거리 | 앞으로 60일의 천문 현상을 모아 레슨으로 잇는다 | `assets/sky-events.js` · `components/sky-events-dialog.vue` |
| 관측 기록 | 밖에서 본 것을 적어 두고 CSV 로 내보낸다 | `assets/observation-log.js` · `components/observation-log-dialog.vue` |

셋 다 같은 자리에 걸려 있습니다. 새 항목을 더할 때 참고하세요.

```
store/index.js        show<이름>Dialog 플래그
App.vue               menuItems 에 한 줄
components/gui.vue    import · dialogs 목록 · components
locales/<lang>.json   네 언어 전부
```

`store_show_menu_item` 은 상류가 임베드용으로 두고 간 것입니다. 값이
`false` 면 그 항목이 숨습니다. 우리는 넣지 않으므로 항상 보입니다.

## 1. 하늘 밝기

**엔진에 `core.bortle_index` 가 처음부터 있었는데 아무도 쓰지 않고
있었습니다.** 기본값이 3, 곧 시골 하늘입니다.

그래서 도시에 사는 사람은 **자기가 결코 볼 수 없는 하늘**을 화면으로
보면서 레슨의 "밖에 나가 찾아보세요"를 읽습니다. 나가서 못 찾고, 자기가
뭘 잘못했다고 생각합니다. 이것을 고치려고 만들었습니다.

값 하나가 엔진 안에서 세 군데를 동시에 바꿉니다.

| 어디 | 무엇 |
|---|---|
| `src/core.c` `core_get_point_for_mag_` | 별 점의 반지름. 어두운 별이 사라진다 |
| `src/modules/atmosphere.c` | 광공해 밝기. 배경이 밝아진다 |
| `src/modules/dss.c` | 겹쳐 보는 사진의 세기 |

보틀 등급 1~9 를 다섯 자리로 추렸습니다. 아홉 단계를 그대로 내놓으면
고르는 사람이 자기가 어디인지 판단할 수 없습니다. 항목마다 **거기서 몇
등급까지 보이는지**를 함께 적어 설정 자체가 한 줄짜리 수업이 되게 했습니다.

캔버스에서 직접 재 본 값입니다. 2026-08-22 23시, 남쪽 하늘, 시야 70도,
화면 가운데 영역:

| 보틀 | 하늘 배경 | 별 픽셀 |
|---|---|---|
| 1 아주 어두운 곳 | 30.9 | 911 |
| 3 시골 | 34.0 | 606 |
| 5 교외 | 42.9 | 364 |
| 7 도시 변두리 | 54.7 | 183 |
| 9 도시 한복판 | 67.7 | 52 |

### 레슨과 부딪히는 것을 어떻게 풀었나

**레슨이 도는 동안에는 사용자 설정과 상관없이 시골 하늘(3)로 고정합니다.**
레슨 본문의 "은하수가 삼각형을 가로지릅니다" 같은 문장은 그 하늘을 보고
쓴 것이라 도시 하늘 위에서는 헛말이 됩니다.

`director.js` 의 `capture` 에서 밀어 두고 `reset` 에서 되돌립니다. 되돌릴
때 **붙잡아 둔 값이 아니라 저장된 설정에서 읽습니다.** 관측지와 같은
이유입니다 — 이 값의 주인은 엔진이 아니라 앱이고, 레슨을 읽는 도중에
설정을 바꿨을 수도 있습니다.

> **남은 긴장**: 그래서 레슨 안에서는 이 설정이 무력합니다. "도시에 사는
> 사람에게 시골 하늘을 보여준다"는 문제가 정작 "밖에 나가라"고 말하는
> 자리에서는 그대로입니다. 본문이 "당신의 하늘은 보틀 8이니 이건 안
> 보입니다" 라고 알려 주는 쪽이 옳지만, 그건 19편 × 4개 언어를 손대는
> 일입니다. 지금은 창 아래에 사정을 밝혀 두었습니다.

## 2. 이번 달 볼거리

레슨은 **일부러 연도를 쓰지 않습니다.** 별자리는 해마다 같은 자리에 오므로
"8월에 남쪽 하늘"이면 충분하고, 연도를 박으면 이듬해에 거짓말이 됩니다.
그 대가로 **"그래서 언제"가 비어 있었습니다.** 「오늘 밤」 탭은 오늘만 보고
레슨은 아무 날에나 맞으니 그 사이가 없었습니다.

앞으로 60일 사이의 것을 달별로 묶어 냅니다.

| 항목 | 어떻게 |
|---|---|
| 삭 · 보름 | 달–태양 이각의 골과 마루 |
| 상현 · 하현 | 이각이 90도를 **올라가며** 지나는지 **내려오며** 지나는지 |
| 유성우 극대일 | `skydata/meteor-showers.json` + 그날 달의 조명 비율 |
| 충 | 바깥 행성 이각의 마루가 170도를 넘을 때 |
| 최대이각 | 안쪽 행성 이각의 마루. 해의 동/서로 저녁·새벽을 가른다 |
| 접근 | 달·행성 여섯을 짝지어 4도 안으로 드는 골 |

상현과 하현을 **조명 비율로 가르면 안 됩니다.** 둘 다 0.5 입니다.
오르내리는 방향이 있어야 갈립니다.

각 항목에서 관련 레슨으로 넘어갑니다. **이 다리가 이 화면의 요점입니다** —
유성우 극대일에서 유성우 레슨으로, 달의 위상에서 달 레슨으로.

### 엔진의 calendar API 는 쓸 수 없습니다

`src/js/pre.js` 에 `Module['calendar']` 가 있고 문서까지 달려 있지만,
**이 저장소의 WASM 에 calendar 심벌이 하나도 없습니다.** 부르면
`_calendar_get is not a function` 이 납니다. `src/calendar.c` 자체가
없습니다. 껍데기만 남은 것입니다.

그래서 태양·달·행성의 위치를 직접 훑어 극값과 교차를 찾습니다. 달은
0.25일, 행성은 1일 간격입니다. 서울 기준 전체 계산 **113ms**.

### 날짜만 내고 시각은 내지 않습니다

`getInfo('RADEC')` 이 **지심이 아니라 지평 기준**입니다. 위도 60도와
−60도의 두 관측지에서 달이 **1.38도까지 벌어지는 것을 실측했습니다.**
달은 한 시간에 0.5도쯤 움직이니 위상 시각이 두 시간까지 어긋날 수
있습니다. 날짜는 그래도 맞습니다.

맞지 않는 값을 그럴듯하게 적느니 내지 않는 편이 낫습니다. 화면 아래에
그 사정을 밝히고, 그날 밤 언제 볼지는 「오늘 밤」 탭으로 넘깁니다.

계산은 천문력과 맞습니다. 2026년 9월 삭 `09-11 01:37 UT` · 상현
`09-18 20:50 UT` · 보름 `09-26 16:05 UT` 로 **10~45분 안에서** 맞습니다.

> **알아 둘 것**: 화면은 **관측지의 지방시**로 날짜를 냅니다. 그래서
> 한국에서 보면 위 보름이 **9월 27일**로 뜹니다(01:05 KST). 천문력이
> 흔히 쓰는 UT 날짜(9월 26일)와 하루 어긋나 보이지만 둘 다 맞습니다.
> `moon-phases` 레슨이 보름 장면을 `2026-09-26T20:00+09:00` 으로 잡아 둔
> 것도 문제가 아닙니다 — 그때 달은 이미 99.8% 차 있습니다.

### 유성우 이름

자료 파일의 `designation` 은 **한국어뿐**이라 화면에서 쓸 수 없습니다.
IAU 부호(`PER` · `GEM` …)를 키로 로케일에 넣었습니다. 11개 × 4개 언어.

`build_index.py` 로 유성우를 검색에 넣게 되면(handoff-i18n 6.2) 이름이
두 곳에 생깁니다. **그때 로케일 쪽을 기준으로 삼으세요.**

## 3. 관측 기록

레슨 19편이 전부 "밖에서 해 보세요"로 끝나는데 **돌아왔을 때 적을 곳이
없었습니다.** 「밝기가 변하는 별」 마지막 단계는 글자 그대로 이렇게
시킵니다 — "기록을 남기세요. 날짜 · 시각 · 판단이면 충분합니다. 이것이
관측 자료입니다."

언제 · 무엇을 · 무엇을 보았나 세 칸입니다. 그 문장이 요구하는 그대로입니다.

### 레슨과 이은 자리

마지막 단계 **본문 바로 아래**입니다. 마침 버튼 옆이 아닙니다. 밖에서 할
일을 다 읽은 그 자리가 "적어 두자"는 생각이 드는 자리입니다.

누르면 **그 레슨 이름을 달고** 창이 열립니다(`store.logDraft`). 레슨
이름은 **창을 닫을 때까지 남습니다** — 한 자리에서 두세 줄을 이어 적는
것이 보통인데 첫 줄에만 붙으면 나머지가 어디서 왔는지 모릅니다.

하늘에서 천체를 고른 채로 열면 그 이름이 채워집니다. **천체 정보창이
제목에 쓰는 것과 같은 함수(`swh.namesForSkySource`)** 를 씁니다. 그러지
않으면 화면에 `직녀성`이라 떠 있는데 기록에는 `Alpha Lyrae` 가 적힙니다.

### 서버를 두지 않은 것

이 앱은 계정도 추적도 없는 것이 성질이라 기록도 브라우저 안에만
둡니다(`localStorage`, `byeolmuri.log`). 대신 **그 사실을 창 아래에 밝혀
적었습니다.** 그래서 CSV 내보내기가 곁에 있어야 합니다.

두 가지를 조심했습니다.

- **저장 실패를 삼키지 않습니다.** 저장 공간이 차면 화면에 알립니다.
  조용히 넘어가면 사용자는 자기 관측 자료를 잃습니다
- **CSV 앞에 BOM 을 붙입니다.** 없으면 엑셀이 UTF-8 을 알아보지 못해
  한글과 일본어 기록이 깨진 채로 열립니다. 소스에서는 `'﻿'` 로
  적습니다 — 날 BOM 문자를 넣어 두면 편집기와 도구를 거치며 사라집니다

## 이 과정에서 함께 고친 것

메뉴를 만들다 **로케일에 없는 키를 `$t` 로 부르는 곳 여섯 군데**를
찾았습니다. `formatFallbackMessages` 가 켜져 있어 키 문자열이 그대로
찍히고, **한국어 화면에서도 영어가 뜹니다.**

```
light years · Also known as · more on {0} · Collapse · Expand ·
Equatorial J2000 Grid
```

거리 단위(`light years`)가 가장 아팠습니다. 레슨 여러 편이 "정보창의
거리를 보세요"라고 시키는데 본문은 광년 · 光年 · años luz 라고 짚습니다.
용어집은 그 키가 있다고 적고 있었고 코드 주석도 한국어로 뜬다고 적어
두었는데 **셋 다 어긋나 있었습니다.**

「보기 설정」과 「오늘 밤의 행성」 대화상자의 `Close` 는 아예 하드코딩된
영어였습니다. `$t()` 를 안 거쳐서 키 검사에도 안 걸렸습니다.

**새 화면을 만들면 이 검사를 한 번 돌리세요.** 도구로 만들어 두었습니다.

```bash
cd apps/web-frontend && node tools/check-locale-keys.mjs
```

`src/**/*.{vue,js}` 에서 `$t('...')` 를 모아 네 언어의 로케일과 대조합니다
(플러그인 로케일도 합쳐서 봅니다). 지금은 **키 174개, 빠진 것 0개**입니다.

**이 검사가 못 잡는 것이 있습니다.** 아예 하드코딩된 영어는 `$t()` 를
거치지 않으니 걸리지 않습니다. 위의 `Close` 두 곳이 그랬습니다. 그리고
`$t('learn.level.' + x)` 처럼 이어 붙이는 키도 검사할 수 없습니다.
**새 화면은 네 언어로 한 번씩 열어 보세요.**
